# ⚡ SYNTRA

### Adaptive Multi-Key LLM Question Answering Chatbot

> **Fast answers. Intelligent routing. Zero unnecessary downtime.**

SYNTRA is a modern, low-latency **LLM-powered Question Answering Chatbot** designed to provide fast and reliable responses while solving a practical problem in LLM-based applications: **API quota exhaustion and rate limiting**.

Instead of depending on a single API key, SYNTRA uses an **Adaptive API Routing and Fallback Mechanism** that automatically detects unavailable, rate-limited, or exhausted API keys and routes the request through another available key.

The system combines **LLM-based question answering, intelligent API routing, automatic failure recovery, streaming responses, and a polished neon-themed interface** into a single application.

---

## ✨ Key Features

### 🧠 LLM-Powered Question Answering

Ask natural-language questions and receive contextual responses generated by a Large Language Model.

### 🔄 Adaptive API Key Routing

SYNTRA dynamically manages multiple API keys and selects an available key for each request.

```text
User Query
    ↓
API Router
    ↓
Key 1 ──→ ❌ Quota Exhausted
    ↓
Key 2 ──→ ❌ Rate Limited
    ↓
Key 3 ──→ ✅ Available
    ↓
LLM Response
```

### 🛡️ Automatic Failover

If an API request fails because of:

* Quota exhaustion
* Rate limiting
* Temporary API errors
* Provider unavailability
* Connection failures

SYNTRA automatically attempts another available API key instead of immediately failing the user's request.

### ⚡ Low-Latency Responses

The system is designed with performance in mind using:

* Asynchronous backend processing
* Streaming responses
* Efficient API routing
* Minimal unnecessary processing
* Connection reuse where applicable

### 📡 Real-Time Streaming

Responses can be displayed progressively instead of waiting for the complete answer.

```text

```

This improves the perceived responsiveness of the chatbot.

### 📊 API Health Monitoring

SYNTRA maintains the state of API keys and tracks their availability.

Example:

```text

● KEY-02    HEALTHY
● KEY-03    RATE LIMITED
● KEY-04    QUOTA EXHAUSTED
```

SYNTRA features a futuristic interface with:

# 🔥 Novelty

The primary novelty of SYNTRA is its **Adaptive Multi-Key LLM API Routing System**.

Traditional chatbot implementations generally depend on a single API key:

```text
User → Backend → API Key → LLM
```

When the key reaches its quota:

```text
User → Backend → API ❌
```

SYNTRA introduces an additional routing layer:

```text
User
 ↓
Request Manager
 ↓
Adaptive API Router
 ↓
Check Key Health
 ↓
Select Available Key
 ↓
LLM
 ↓
Response
```

If the selected key becomes unavailable, the router automatically attempts another eligible key.

This improves the **resilience and availability** of the application.

# 🧩 API Routing Strategy

Each API key can maintain a state such as:

```text
HEALTHY
RATE_LIMITED
QUOTA_EXHAUSTED
FAILED
COOLDOWN
```

The router can use factors such as:

* Current key status
* Previous failures
* Rate-limit responses
* Cooldown period
* Response latency
* Availability

A simplified routing process:

```text
                    Request
                       │
                       ▼
                Select API Key
                       │
                       ▼
                 Send Request
                       │
             ┌─────────┴─────────┐
             │                   │
           Success             Failure
             │                   │
             ▼                   ▼
          Response          Classify Error
                                 │
                       ┌─────────┴─────────┐
                       │                   │
                    Temporary          Exhausted
                       │                   │
                       ▼                   ▼
                   Retry/Wait         Next Key
                                           │
                                           ▼
                                    Send Request
```

# ⚙️ Installation

### 1. Clone the repository

```bash
git clone https://github.com/your-username/syntra.git
cd syntra
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate it:

**Windows**

```bash
venv\Scripts\activate
```

**Linux/macOS**

```bash
source venv/bin/activate
```

### 3. Install backend dependencies

```bash
pip install -r backend/requirements.txt
```

### 4. Install frontend dependencies

```bash
cd frontend
npm install
```

### 5. Configure API keys

Create a `.env` file:

```env
LLM_API_KEY_1=your_first_api_key
LLM_API_KEY_2=your_second_api_key
LLM_API_KEY_3=your_third_api_key
```

> **Never commit your `.env` file or API keys to GitHub.**

SYNTRA follows basic API security practices:

* API keys never exposed to the frontend
* Backend handles all LLM API communication
